## 과제 개요

- 이 과제에서는 시작 코드 없이 서버를 직접 설계하고, 명세의 빈틈을 찾아 합리적으로 결정할 수 있는지를 봅니다.
- 포트폴리오 서버 1개를 처음부터 구현합니다.
  - 기술 스택은 Java 17, Spring Boot 4.1.1, Gradle, JPA, H2입니다.
- 가상 시세 서버(Docker 이미지), 상품 데이터 파일, 문서 템플릿을 제공합니다.
- 제한 시간은 없습니다.
- 상품 데이터에는 중복과 서로 다른 표기가 섞여 있습니다. 시세 서버는 토큰이 만료되고, 가끔 응답이 불안정합니다.

## 1. 과제 소개

투자 앱의 서버를 만드는 과제입니다.

- 사용자는 투자 상품 목록을 보고, 원하는 상품을 골라 포트폴리오를 만듭니다.
- 상품 가격이 바뀌면 포트폴리오의 수익률을 확인할 수 있어야 합니다.

서버는 처음부터 직접 구현합니다. 상품 데이터 파일과, 시세를 알려 주는 외부 서버를 제공합니다.

> [!TIP]
> 이 과제에서 확인하는 것은 다음과 같습니다.
> - 명세를 끝까지 읽고 적힌 대로 구현했는가
> - 명세에 적혀 있지 않은 부분을 찾아 결정하고, 그 이유를 기록했는가
> - 시작 코드 없이 데이터 모델, 외부 연동, 주기 작업을 직접 설계했는가
> - 주어진 데이터를 검증 없이 그대로 쓰지 않았는가

> [!IMPORTANT]
> - 이 문서에는 일부러 정해 두지 않은 부분이 있습니다.
> - 그런 부분을 찾아서 결정하고 `docs/assumptions.md`에 기록하는 것도 과제에 포함됩니다.

## 3. 시작하기

1. 가상 시세 서버를 실행합니다.
   - `compose.yaml`이 이미지를 자동으로 내려받으므로, 파일을 따로 내려받거나 `docker load`를 실행할 필요가 없습니다.
   ```bash
   docker compose up
   ```
2. `http://localhost:9091/swagger-ui.html`에서 시세 서버 API를 확인합니다.
3. `data/products.csv`를 `starter-project/data/products.csv`로 복사합니다. **이 파일은 수정하지 않습니다.**
4. 구현할 서버는 `./gradlew bootRun`으로 `8080` 포트에서 실행합니다.
5. 시세 서버 주소는 환경변수 `PRICE_BASE_URL`로 바꿀 수 있게 구현합니다. 기본값은 `http://localhost:9091`입니다.

## 4. 용어 설명

| 용어 | 뜻 |
|---|---|
| **포트폴리오** | 사용자가 고른 투자 상품과 수량의 묶음 |
| **매입가** | 상품을 포트폴리오에 담은 시점의 가격 |
| **매입금액(원가)** | 매입가 × 수량을 모두 더한 값 |
| **평가금액** | 현재 가격 × 수량을 모두 더한 값 |
| **수익률** | (평가금액 − 매입금액) ÷ 매입금액 × 100 |
| **토큰 (액세스 토큰)** | 외부 서버가 발급하는 임시 인증 값. 일정 시간이 지나면 만료됩니다. |
| **스케줄링** | 정해진 주기마다 작업을 자동으로 실행하는 것 |
| **가정** | 명세에 없는 부분에 대해 직접 내린 결정. 이유와 함께 기록해야 합니다. |

## 5. 구현할 API 명세

- 정해진 경로와 필드는 그대로 지켜야 합니다.
- 그 밖의 필드나 API는 자유롭게 추가할 수 있습니다. 추가한 내용은 `docs/api.md`에 적어 주세요.

### 5-1. 상품 조회

`GET /api/v1/products?query=&type=&currency=&riskLevel=&sort=&page=&size=`

| 파라미터 | 규칙 |
|---|---|
| `query` | 코드, 이름, 영문명 중 하나라도 부분 일치하면 검색됩니다. 영문은 대소문자를 구분하지 않습니다. |
| `type` | `ETF`, `FUND`, `BOND` |
| `currency` | `KRW`, `USD` |
| `riskLevel` | 1~5 |
| `sort` | `필드,방향` 형식. 필드는 `code`, `name`, `listedDate`, `riskLevel`, 방향은 `asc`, `desc`입니다. 기본값은 `code,asc`입니다. |
| `page`, `size` | `page`는 0 이상, `size`는 1~100 (기본값 20) |
| 필터 조합 | 서로 다른 필터를 함께 쓰면 **AND** 조건으로 동작합니다. |

**응답**

```json
{
  "items": [ { "code": "A001", "name": "...", "nameEn": "...", "type": "ETF", "currency": "KRW",
               "riskLevel": 3, "issuer": "...", "listedDate": "2020-01-05", "currentPrice": 1200 } ],
  "page": 0, "size": 20, "totalElements": 1, "totalPages": 1
}
```

- `currency`는 `KRW` 또는 `USD`로, `listedDate`는 `yyyy-MM-dd` 형식으로 응답합니다.
- `riskLevel`이 없는 상품은 `null`로 응답합니다.
- `currentPrice`는 최신 시세이며, 아직 시세가 없으면 `null`로 응답합니다.

### 5-2. 포트폴리오

| API | 내용 |
|---|---|
| `POST /api/v1/portfolios` | 생성. **201**과 함께 상세 조회와 같은 형식으로 응답 |
| `GET /api/v1/portfolios/{id}` | 상세 조회 (평가 결과 포함) |
| `GET /api/v1/portfolios?query=&sort=&page=&size=` | 목록 조회. `query`는 이름 부분 일치(대소문자 무시). `sort` 필드는 `name`, `createdAt`, `returnRate`, `totalValue` (기본값 `createdAt,desc`) |
| `PUT /api/v1/portfolios/{id}` | 이름과 보유 종목을 **전체 교체**. 200 응답 |
| `DELETE /api/v1/portfolios/{id}` | 삭제. **204** 응답 |

**생성 및 수정 요청**

```json
{ "name": "내 포트폴리오", "holdings": [ { "code": "A001", "quantity": 10 }, { "code": "A002", "quantity": 5 } ] }
```

**상세 응답**

- 아래 필드는 반드시 포함해야 합니다. 다른 필드는 자유롭게 추가할 수 있습니다.

```json
{
  "id": 1, "name": "내 포트폴리오", "createdAt": "2026-09-21T10:00:00",
  "holdings": [ { "code": "A001", "quantity": 10, "purchasePrice": 1000, "currentPrice": 1200 } ],
  "summary": { "totalCost": 10000, "totalValue": 12000, "profit": 2000, "returnRate": 20.00,
               "todayProfit": 500, "asOf": "2026-09-21T10:00:30" }
}
```

| 필드 | 뜻 |
|---|---|
| `totalCost` | 매입금액 (원) |
| `totalValue` | 평가금액 (원) |
| `profit` | 수익금 (원) |
| `returnRate` | 수익률 (%) |
| `todayProfit` | **오늘 손익** (원) |
| `asOf` | 계산에 사용한 시세의 기준 시각 |

- `id`는 숫자와 문자열 중 어느 형식이어도 됩니다.
- 목록 조회의 각 항목에는 `id`, `name`, `totalValue`, `returnRate`, `createdAt`이 있어야 합니다.

**입력 규칙**

| 필드 | 규칙 |
|---|---|
| `name` | 1~50자 |
| `holdings` | 1~20개. 같은 `code`를 두 번 넣을 수 없습니다. |
| `quantity` | 1 이상 1,000,000 이하 정수 |
| `code` | 존재하는 상품 코드여야 합니다. |

| 상황 | 상태 코드 | 본문 |
|---|---|---|
| 입력 오류 | **400** | `{"code":"INVALID_REQUEST","message":"..."}` |
| 존재하지 않는 상품 코드 | **400** | `{"code":"UNKNOWN_PRODUCT","message":"..."}` |
| 없는 포트폴리오 | **404** | `{"code":"PORTFOLIO_NOT_FOUND","message":"..."}` |
| 아직 시세가 없음 (생성, 수정) | **503** | `{"code":"PRICE_NOT_READY","message":"..."}` |

## 6. 계산 규칙

| 규칙 | 내용 |
|---|---|
| 매입가 | 종목을 포트폴리오에 담는 시점에 **가장 최근에 받아 둔 시세**로 정합니다. 이후 시세가 바뀌어도 **매입가는 바뀌지 않습니다.** |
| 매입금액 | 종목별 `수량 × 매입가`의 합 |
| 평가금액 | 종목별 `수량 × 현재가`의 합 |
| 수익금 | 평가금액 − 매입금액 |
| 수익률 | 수익금 ÷ 매입금액 × 100 (%) |
| 시세 갱신 | **30초마다** 시세 서버에서 시세를 가져옵니다. |
| 아직 시세가 없을 때 | 포트폴리오 생성과 수정은 503을 응답합니다. |
| 시세 서버 장애 | 시세를 가져오지 못해도 **포트폴리오 조회 API는 응답해야 합니다.** 이때 무엇을 보여 줄지는 직접 정합니다. |

> [!IMPORTANT]
> **반올림 규칙**
> - 금액(원)은 원 단위 미만을 버립니다.
> - 수익률은 소수 둘째 자리까지 반올림(HALF_UP)합니다.
> - 두 규칙을 섞어 쓰지 않도록 주의해 주세요.

## 7. 가상 시세 서버 API 명세

- 주소: `http://localhost:9091`
- 자세한 명세는 Swagger(`http://localhost:9091/swagger-ui.html`)에서 확인할 수 있습니다.

### 토큰 발급

`POST /auth/token`

```json
{ "clientId": "student", "clientSecret": "student-secret" }
```

응답 (200)

```json
{ "accessToken": "eyJ...", "tokenType": "Bearer", "expiresIn": 120 }
```

- `expiresIn`은 초 단위입니다. 이 시간이 지나면 토큰을 사용할 수 없습니다.
- 인증 정보가 틀리면 401을 응답합니다.

### 시세 조회

`GET /v1/prices` (헤더 `Authorization: Bearer <토큰>`)

```json
{ "asOf": "2026-09-21T10:00:30", "prices": [ { "code": "A001", "price": 1200, "currency": "KRW" } ] }
```

### 환율 조회

`GET /v1/fx?pair=USD-KRW` (헤더 `Authorization: Bearer <토큰>`)

```json
{ "pair": "USD-KRW", "rate": 1350.25, "asOf": "2026-09-21T10:00:30" }
```

### 참고 사항

- 시세와 환율은 30초마다 바뀝니다.
- 원화 상품의 가격은 정수이고, 달러 상품의 가격과 환율은 소수 둘째 자리까지 있습니다.
- 토큰이 없거나 만료되면 **401**(`TOKEN_EXPIRED` 또는 `UNAUTHORIZED`)을 응답합니다.
- 시세 서버가 일시적으로 불안정하면 **503**을 응답할 수 있습니다.

## 8. 명세에 없는 부분과 가정 문서

이 과제의 명세에는 일부러 정하지 않은 부분이 있습니다. 실제 업무에서도 요구사항에는 빈틈이 있고, 개발자가 이를 발견해 질문하거나 직접 결정해야 하는 경우가 많습니다.

- 요구사항을 읽으면서 이 경우에는 어떻게 해야 할지 판단이 필요한 부분을 **3개 이상** 찾아 주세요.
- 각 부분을 어떻게 결정했고 왜 그렇게 했는지 `docs/assumptions.md`에 기록해 주세요.
- **결정한 내용은 코드에 실제로 반영되어야 합니다.** 문서와 실제 동작이 다르면 감점됩니다.
- 정해진 답은 없습니다. 이유가 타당한지를 평가합니다.

**가정 문서 템플릿** (`docs/assumptions.md`)

```markdown
# 가정 문서

| # | 상황 (명세에 없는 부분) | 나의 결정 | 이유 | 고려한 다른 선택지 | 코드 위치 | 실무라면 확인할 질문 |
|---|---|---|---|---|---|---|
| 1 | | | | | | |
| 2 | | | | | | |
| 3 | | | | | | |
```

| R1 | 서버가 시작될 때 `data/products.csv`를 읽어 상품을 저장합니다. 파일은 수정하지 않습니다. |
| R2 | 상품 조회 API (검색, 정렬, 필터, 페이지) |
| R3 | 포트폴리오 생성, 조회, 목록, 수정, 삭제 API |
| R4 | **30초마다** 시세 서버에서 시세와 환율을 가져와 평가금액에 반영합니다. |
| R5 | 시세 서버의 토큰이 만료되어도 시세 갱신이 계속되어야 합니다. |
| R6 | 시세 서버가 불안정해도 포트폴리오 조회 API는 응답해야 합니다. |
| R7 | 명세에 없는 부분을 찾아 결정하고 `docs/assumptions.md`에 기록합니다. |
| R8 | 추가한 API와 필드를 `docs/api.md`에 기록합니다. |

## 10. 시나리오 체크리스트

| # | 시나리오 | 기대 결과 |
|---|---|---|
| S1 | 상품 검색 | 코드, 이름, 영문명 부분 일치. 영문 대소문자 무시 |
| S2 | 상품 정렬 | 이름, 상장일, 위험등급 정렬 결과가 맞음 |
| S3 | 상품 필터 | 유형, 통화, 위험등급 필터 결과가 맞고, 여러 필터는 AND 조건으로 동작 |
| S4 | 상품 데이터 정리 | 같은 상품이 중복 없이 한 번씩 조회됨. 통화는 `KRW` 또는 `USD`, 상장일은 `yyyy-MM-dd` 형식으로 응답 |
| S5 | 포트폴리오 생성, 조회, 삭제와 입력 검증 | 생성 201, 조회 200, 삭제 204. 잘못된 입력은 400, 없는 ID는 404 |
| S6 | 포트폴리오 목록 | 이름 검색, 정렬, 페이지 처리 |
| S7 | 매입가 고정 | 시세가 바뀌어도 매입가와 매입금액은 그대로이고, 평가금액만 바뀜 |
| S8 | 평가 계산 | 평가금액, 수익금, 수익률이 계산 규칙(반올림 포함)과 일치 |
| S9 | 시세 주기 갱신 | 시세가 바뀌면 **45초 안에** 평가금액에 반영됨 |
| S10 | 토큰 만료 | 토큰이 만료되어도 시세 갱신이 계속되고, **매번 토큰을 새로 발급받지 않음** |
| S11 | 시세 서버 장애 | 시세 서버가 응답하지 않아도 포트폴리오 조회 API가 응답함 |

## 11. 제출 방법

`docs/assumptions.md`와 `docs/api.md`를 포함해 아래 구조로 제출해 주세요.

```
<제출 프로젝트>/
├── build.gradle 등, src/
├── data/products.csv         # 제공된 파일 그대로 (수정 금지)
├── README.md                 # 실행 방법
└── docs/
    ├── api.md                # 직접 만든 API 문서 (추가한 API와 필드 포함)
    └── assumptions.md        # 가정 문서 (템플릿의 표 형식)
```

- 루트에서 `./gradlew bootRun`으로 실행되어야 하며, 포트는 8080입니다.
- 시세 서버 주소는 환경변수 `PRICE_BASE_URL`로 설정합니다. 기본값은 `http://localhost:9091`입니다.
- `data/products.csv`는 **수정하지 않고** 그대로 읽어야 합니다.
- DB는 H2를 사용하며, 별도 설치 없이 실행할 수 있어야 합니다.
- `README.md`에는 실행 방법과 직접 확인한 시나리오를 적어 주세요.
