## 과제 개요

- 빌드 설정만 있는 빈 시작 프로젝트에서 출발해, 포트폴리오 서버 1개의 도메인 코드를 모두 직접 설계하고 구현합니다.
- 가상 시세 서버(Docker 이미지), 상품 데이터 파일, 가정 문서 템플릿을 제공합니다.
- 상품 데이터 파일은 정리된 상태로 제공합니다. 적힌 값을 그대로 믿고 읽으면 됩니다.
- 상품은 80개이고 모두 원화 상품입니다. 가격과 수량이 정수라 금액도 정수로 떨어집니다.
- 시세 서버가 발급한 토큰은 일정 시간 뒤 만료되고, 시세 서버는 가끔 장애를 일으킵니다.
- 기술 스택은 Java 17, Spring Boot 4.1.1, Gradle, JPA, H2입니다. 제한 시간은 없습니다.

## 1. 과제 소개

투자 앱의 서버를 만드는 과제입니다.

- 사용자는 투자 상품 목록을 보고, 원하는 상품을 골라 포트폴리오를 만듭니다.
- 상품 가격이 바뀌면 포트폴리오의 수익률을 확인할 수 있어야 합니다.

상품 데이터 파일과, 시세를 알려 주는 가상 시세 서버를 제공합니다.

> [!TIP]
> 이 과제에서는 세 가지를 확인합니다.
> - 명세를 끝까지 읽고 적힌 대로 구현했는가
> - 외부 서버 연동과 주기 작업을 직접 설계했는가
> - 명세에 적혀 있지 않은 부분을 찾아 결정하고, 그 이유를 기록했는가

## 2. 구현 범위와 제공 자료

- 서버 1개를 구현합니다. 상품 조회, 포트폴리오 관리, 시세 갱신, 수익률 계산 기능이 필요합니다.
- 가상 시세 서버(Docker 이미지), 상품 데이터 파일, 이 문서, 가정 문서 템플릿, 요청 예시를 제공합니다.

## 3. 시작하기

JDK 17과 Docker가 필요합니다. 아래 명령은 모두 `starter-project/` 폴더에서 실행합니다.

1. 가상 시세 서버를 실행합니다. 이미지는 자동으로 내려받습니다.
   ```bash
   cd starter-project
   docker compose up -d
   ```
2. 브라우저에서 `http://localhost:9091/swagger-ui.html`을 엽니다. 시세 서버 API를 보고 직접 호출해 볼 수 있는 문서 화면(Swagger)입니다.
3. 서버를 실행합니다. 포트는 `8080`입니다.
   ```bash
   ./gradlew bootRun
   ```

## 4. 용어 설명

| 용어 | 뜻 |
|---|---|
| **포트폴리오** | 사용자가 고른 투자 상품과 수량의 묶음. 포트폴리오에 담긴 상품을 보유 상품(`holdings`)이라고 부릅니다. |
| **시세 (현재가)** | 시세 서버가 알려 주는 상품의 최신 가격 |
| **매입가** | 상품을 포트폴리오에 담은 시점의 가격 |
| **매입금액(원가)** | 매입가 × 수량을 모두 더한 값 |
| **평가금액** | 현재가 × 수량을 모두 더한 값 |
| **수익금** | 평가금액 − 매입금액 |
| **수익률** | 수익금 ÷ 매입금액 × 100 |
| **토큰 (액세스 토큰)** | 시세 서버가 발급하는 임시 인증 값. 일정 시간이 지나면 만료됩니다. |
| **시세 갱신 작업** | 정해진 주기마다 시세 서버에서 시세를 가져오는 작업 |
| **시세 서버 장애** | 시세 서버가 503을 응답하거나, 정해진 시간 안에 응답하지 않는 상황 |
| **가정** | 명세에 없는 부분에 대해 직접 내린 결정. 이유와 함께 기록해야 합니다. |

## 5. 구현할 API 명세

- 정해진 경로와 필드는 그대로 지켜야 합니다.
- 그 밖의 필드나 API는 자유롭게 추가할 수 있습니다. 추가한 내용은 제출 README에 적어 주세요.
- 에러 응답은 모두 `{"code":"...","message":"..."}` 형식입니다.

### 5-1. 상품 조회

`GET /api/v1/products`

- 파라미터는 없습니다. 상품 80개를 상품 코드 오름차순 배열로 응답합니다.
- 검색, 정렬, 필터, 페이지 처리는 이 과제의 범위가 아닙니다.

**응답** (값은 예시입니다)

```json
[
  { "code": "A001", "name": "가상 성장 채권 01", "type": "BOND", "currentPrice": 10000 },
  { "code": "A002", "name": "가상 배당 ETF 01", "type": "ETF", "currentPrice": 84500 }
]
```

- `type`은 `ETF`, `FUND`, `BOND` 중 하나입니다.
- `currentPrice`는 현재가이며, 아직 시세가 없으면 `null`로 응답합니다.

### 5-2. 포트폴리오

| API | 내용 |
|---|---|
| `POST /api/v1/portfolios` | 생성. **201**과 함께 상세 응답 형식으로 응답 |
| `GET /api/v1/portfolios/{id}` | 상세 조회. 평가금액, 수익금, 수익률 포함 |
| `GET /api/v1/portfolios` | 목록 조회. 만든 순서대로 배열로 응답 |
| `PUT /api/v1/portfolios/{id}` | 이름과 보유 상품을 **전체 교체**. **200**과 함께 상세 응답 형식으로 응답 |
| `DELETE /api/v1/portfolios/{id}` | 삭제. **204** 응답 (본문 없음) |

**생성 및 수정 요청**

```json
{ "name": "내 포트폴리오", "holdings": [ { "code": "A001", "quantity": 10 }, { "code": "A002", "quantity": 5 } ] }
```

**상세 응답**

- 아래 필드는 반드시 포함해야 합니다. 다른 필드는 자유롭게 추가할 수 있습니다.
- 응답 JSON의 `id`는 숫자(`1`)나 문자열(`"1"`) 어느 쪽이어도 됩니다.

```json
{
  "id": 1, "name": "내 포트폴리오",
  "holdings": [ { "code": "A001", "quantity": 10, "purchasePrice": 10000, "currentPrice": 11000 } ],
  "summary": { "totalCost": 100000, "totalValue": 110000, "profit": 10000, "returnRate": 10.00,
               "asOf": "2026-09-21T10:00:30.123456789Z" }
}
```

| 필드 | 뜻 |
|---|---|
| `totalCost` | 매입금액 (원) |
| `totalValue` | 평가금액 (원) |
| `profit` | 수익금 (원) |
| `returnRate` | 수익률 (%) |
| `asOf` | 계산에 쓴 시세의 기준 시각 |

**목록 응답**

```json
[ { "id": 1, "name": "내 포트폴리오", "totalValue": 110000, "returnRate": 10.00 } ]
```

**입력 규칙**

| 필드 | 규칙 |
|---|---|
| `name` | 1~50자 |
| `holdings` | 1~20개. 같은 `code`를 두 번 넣을 수 없습니다. |
| `quantity` | 1 이상 1,000,000 이하 정수 |
| `code` | 존재하는 상품 코드여야 합니다. |

| 상황 | 상태 코드 | 본문 |
|---|---|---|
| 입력 규칙 위반 (상품 코드 존재 여부 제외) | **400** | `{"code":"INVALID_REQUEST","message":"..."}` |
| 존재하지 않는 상품 코드 | **400** | `{"code":"UNKNOWN_PRODUCT","message":"..."}` |
| 없는 포트폴리오 | **404** | `{"code":"PORTFOLIO_NOT_FOUND","message":"..."}` |
| 담으려는 상품의 시세를 아직 받지 못함 (생성, 수정) | **503** | `{"code":"PRICE_NOT_READY","message":"..."}` |

## 6. 계산 규칙

| 규칙 | 내용 |
|---|---|
| 매입가 | 상품을 포트폴리오에 담는 시점에 **가장 최근에 받아 둔 시세**로 정합니다. 이후 시세가 바뀌어도 **매입가는 바뀌지 않습니다.** |
| 수정할 때의 매입가 | 수정 API는 보유 상품을 전체 교체합니다. 교체된 보유 상품의 매입가는 **모두 수정 시점의 시세로 다시 정합니다.** |
| 매입금액 | 보유 상품별 `수량 × 매입가`의 합 |
| 평가금액 | 보유 상품별 `수량 × 현재가`의 합 |
| 수익금 | 평가금액 − 매입금액 |
| 수익률 | 수익금 ÷ 매입금액 × 100 (%) |
| 시세 갱신 | **30초마다** 시세 서버에서 시세를 가져옵니다. |
| 시세를 아직 받지 못했을 때 | 그 상품을 담는 포트폴리오 생성과 수정은 503을 응답합니다. |
| 시세 서버 장애 | 시세를 가져오지 못해도 **GET API(상품 조회, 포트폴리오 상세 조회, 목록 조회)는 5xx 없이 응답해야 합니다.** 이때 무엇을 보여 줄지는 직접 정합니다. |

> [!IMPORTANT]
> **수익률 반올림 규칙**
> - 수익률은 소수 셋째 자리에서 반올림해 소수 둘째 자리까지 나타냅니다. 0.005 이상이면 올립니다(Java의 `RoundingMode.HALF_UP`). 예: 12.345% → 12.35%
> - 금액은 모두 정수입니다. 상품 가격과 수량이 정수라서 매입금액, 평가금액, 수익금에 소수가 생기지 않습니다.
>
> **계산 예시** (`A001`을 10주 보유, 매입가 10,000원 → 현재가 11,000원)
> | 항목 | 계산 | 응답 값 |
> |---|---|---|
> | `totalCost` | 10 × 10,000 | **100,000** |
> | `totalValue` | 10 × 11,000 | **110,000** |
> | `profit` | 110,000 − 100,000 | **10,000** |
> | `returnRate` | 10,000 ÷ 100,000 × 100 | **10.00** |

## 7. 가상 시세 서버 API 명세

- 주소: `http://localhost:9091`
- 자세한 명세는 Swagger(`http://localhost:9091/swagger-ui.html`)에서 확인할 수 있습니다.

### 토큰 발급

`POST /auth/token`

```json
{ "clientId": "client", "clientSecret": "client-secret" }
```

응답 (200)

```json
{ "accessToken": "eyJ...", "tokenType": "Bearer", "expiresIn": 120 }
```

- 발급 후 `expiresIn`초가 지나면 이 토큰을 사용할 수 없습니다.
- `clientId`나 `clientSecret`이 틀리면 401을 응답합니다.

### 시세 조회

`GET /v1/prices` (헤더 `Authorization: Bearer <토큰>`)

```json
{ "asOf": "2026-09-21T10:00:30.123456789Z", "prices": [ { "code": "A001", "price": 11000, "currency": "KRW" } ] }
```

- 응답에는 이 과제에서 쓰지 않는 상품도 섞여 있습니다. `data/products.csv`에 있는 상품만 쓰면 됩니다.

### 참고 사항

- 시세는 30초마다 바뀝니다.
- `asOf`는 **UTC 기준 ISO-8601 형식**이며 `Z`로 끝나고 소수 이하 자리가 붙습니다. 한국 시간(`LocalDateTime`)으로 바로 매핑하면 파싱에 실패하니 주의해 주세요.
- 토큰 문제로 실패하면 **401**을 응답합니다. 본문의 `code`가 `TOKEN_EXPIRED`면 만료된 토큰, `UNAUTHORIZED`면 없거나 잘못된 토큰입니다.
- 시세 서버는 가끔 **503**을 응답합니다. 응답이 오래 걸리는 경우에도 대비해 주세요.
- 시세와 503 응답은 그때그때 정해집니다. 같은 요청을 다시 보내도 값이 다를 수 있습니다. 원하는 상황을 바로 만들려면 아래 [시나리오 재현 API](#시나리오-재현-api)를 사용해 주세요.

### 시나리오 재현 API

시세는 30초마다 바뀌고 서버는 가끔 실패하기 때문에, 10장의 S4부터 S8까지를 원하는 때에 확인하기 어렵습니다. 아래 API로 상황을 먼저 만들어 두면 바로 확인할 수 있습니다.

구현한 서버가 시나리오대로 동작하는지 확인하는 용도이므로, 제출하는 코드에서 이 API를 호출할 필요는 없습니다.

| API | 하는 일 |
|---|---|
| `POST /sandbox/prices` | 지정한 상품의 현재가를 그 값으로 고정합니다 |
| `POST /sandbox/server` | 시세 서버가 어떤 상태로 동작할지 고릅니다 |
| `POST /sandbox/tokens/expire` | 발급된 토큰을 즉시 만료시킵니다 |
| `GET /sandbox/requests` | 시세 서버가 받은 호출을 순서대로 보여 줍니다 |
| `POST /sandbox/reset` | 고정한 값과 기록을 모두 처음으로 되돌립니다 |

가격을 고정하면 계산 결과를 손으로 검산할 수 있습니다.

```bash
curl -X POST http://localhost:9091/sandbox/prices \
  -H 'Content-Type: application/json' \
  -d '{"prices":{"A001":10000}}'
```

- 고정한 상품만 멈추고 나머지는 계속 변합니다. 같은 상품을 다른 값으로 다시 보내면 시세가 바뀐 상황이 됩니다(S4, S6).
- 없는 상품 코드를 보내면 응답의 `ignored`에 나옵니다.

서버 상태는 네 가지 중 하나를 고릅니다.

| `case` | 시세 서버가 하는 일 | 확인하는 시나리오 |
|---|---|---|
| `RANDOM` | 기본 상태입니다. 가끔 실패하고 응답 시간도 조금씩 다릅니다 | 마지막 점검 |
| `STABLE` | 실패하지 않습니다 | S6, S7을 확인할 때의 전제 |
| `ALWAYS_FAIL` | 항상 503을 응답합니다 | S8 |
| `ALWAYS_SLOW` | 응답이 아주 오래 걸립니다. 그 뒤에는 정상 응답합니다 | S8의 지연 경로 |

```bash
curl -X POST http://localhost:9091/sandbox/server \
  -H 'Content-Type: application/json' -d '{"case":"ALWAYS_FAIL"}'
```

`GET /sandbox/requests`로 시세 서버가 받은 호출을 볼 수 있습니다. `PRICES` 사이의 간격으로 갱신 주기를(S6), `tokenPrefix`가 같은지로 토큰을 다시 쓰는지를(S7) 확인해 주세요. 503으로 실패한 호출도 함께 남습니다.

- `POST /sandbox/reset`을 호출하면 서버 상태가 `RANDOM`으로 돌아옵니다. 실패하지 않는 상태가 필요하면 다시 지정해 주세요.
- 시세 서버가 아예 꺼진 경우(연결 실패)는 이 API로 만들 수 없습니다. `docker compose stop price-server`로 직접 내려서 확인해 주세요.

## 8. 명세에 없는 부분과 가정 문서

이 과제의 명세에는 일부러 정하지 않은 부분이 한 곳 있습니다. 실제 업무에서도 요구사항에는 빈틈이 있고, 개발자가 이를 발견해 질문하거나 직접 결정해야 하는 경우가 많습니다.

**시세를 가져오지 못했을 때 사용자에게 무엇을 보여 줄지**는 정해 두지 않았습니다. 6장은 GET API가 5xx 없이 응답해야 한다고만 적었고, 그때 어떤 값을 보여 줄지는 적지 않았습니다.

- 어떻게 결정했고 왜 그렇게 했는지, **함께 검토한 다른 선택지**와 **실무라면 기획자에게 확인할 질문**까지 `starter-project/docs/assumptions.md`에 기록해 주세요.
- 위 한 곳 **말고도** 정해지지 않은 부분을 찾았다면 함께 적어 주세요. 기록의 설득력을 높이는 데 반영됩니다.
- **결정한 내용은 코드에 실제로 반영되어야 합니다.** 문서와 실제 동작이 다르면 감점됩니다.
- 명세에 없는 부분에는 정해진 답이 없습니다. 이유가 타당한지를 평가합니다.

**가정 문서 템플릿** (`docs/assumptions.md`)

```markdown
# 가정 문서

| # | 상황 (명세에 없는 부분) | 나의 결정 | 이유 | 고려한 다른 선택지 | 코드 위치 (예: 클래스#메서드) | 실무라면 기획자에게 확인할 질문 |
|---|---|---|---|---|---|---|
| 1 | | | | | | |
```

| R3 | 포트폴리오 생성, 조회, 목록, 수정, 삭제 API |

| R5 | 시세 서버의 토큰이 만료되어도 시세 갱신이 계속되어야 합니다. |
| R6 | 시세 서버에 장애가 있어도 GET API는 5xx 없이 응답해야 합니다. |
| R7 | 명세에 없는 부분을 결정하고 `docs/assumptions.md`에 기록합니다. |

## 10. 시나리오 체크리스트

| # | 시나리오 | 기대 결과 |
|---|---|---|
| S1 | 상품 목록 조회 | 상품 80개가 코드 오름차순 배열로 응답됨 |
| S2 | 포트폴리오 생성, 조회, 삭제와 입력 검증 | 생성 201, 조회 200, 삭제 204. 잘못된 입력은 400, 없는 ID는 404 |
| S3 | 포트폴리오 목록 | 만든 포트폴리오가 배열로 응답되고 `totalValue`, `returnRate`가 들어 있음 |
| S4 | 매입가 고정 | 시세가 바뀌어도 매입가와 매입금액은 그대로이고, 현재가와 평가금액, 수익금, 수익률이 새 시세로 바뀜 |
| S5 | 평가 계산 | 평가금액, 수익금, 수익률이 계산 규칙(수익률 반올림 포함)과 일치 |
| S6 | 시세 주기 갱신 | 시세 서버의 값이 바뀐 뒤 **45초 안에** 평가금액에 반영됨 |
| S7 | 토큰 만료 | 토큰이 만료되어도 시세 갱신이 계속되고, **시세를 가져올 때마다 토큰을 새로 발급받지 않음** |
| S8 | 시세 서버 장애 | 시세 서버에 장애가 있어도 GET API가 5xx 없이 응답함 |

서버와 가상 시세 서버를 띄운 뒤 `starter-project/` 폴더에서 `bash check-scenarios.sh`를 실행하면, 위 시나리오를 한 번에 보내 통과/실패를 색으로 보여 줍니다. 시세를 고정하고 갱신 주기(30초)가 지나기를 기다렸다가 확인하므로 전체가 1~2분쯤 걸립니다. 하나씩 눌러 보고 싶으면 `requests.http`를 쓰세요.

```
<제출 저장소>/
├── build.gradle, settings.gradle, gradlew 등 빌드 파일
├── src/
├── data/products.csv         # 제공된 파일 그대로 (수정 금지)

├── compose.yaml              # 제공된 파일 그대로 (가상 시세 서버 실행용)

└── docs/
    └── assumptions.md        # 가정 문서 (템플릿 형식)
```

- 제출 README는 `starter-project/README.md`의 내용을 지우고 다시 써 주세요.

- `data/products.csv`는 **수정하지 않고** 그대로 읽어야 합니다.
- DB는 H2를 사용하며, 별도 설치 없이 실행할 수 있어야 합니다.
- 제출 전에 `starter-project/` 폴더(제출 저장소의 루트)에서 `bash check-scenarios.sh`를 실행해 시나리오 S1~S8이 모두 통과하는지 확인해 주세요.
